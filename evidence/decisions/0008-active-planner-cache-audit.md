# Active Planner Cache repository cleanup and audit

Date: 2026-08-22

Status: audit complete; no Tool-KV or new memory architecture started.

## Executive result

The active tree now contains only the canonical P-cache, split canonical router,
model-specific translator, durable `.ppkg`, their evaluations, and supporting
representation code. Superseded work is isolated under top-level `Archive/`; active
source, tests, and benchmarks contain no import or path dependency on it.

The audit found and fixed four clear invariant defects:

1. **BLOCKER (fixed):** canonical semantic merge could alias different
   entity/relation identities when their factorized vectors collided. This was the
   cause of the historical 256/512-slot router accuracy decline, not router ranking.
2. **MAJOR (fixed):** stale P-cache slots were still routable. Router indexes now
   exclude slots marked `Freshness.STALE`; invalidated slots remain excluded.
3. **MAJOR (fixed):** canonical P snapshots had format validation but no content
   checksum. Snapshots now checksum tensors plus canonical metadata and reject
   corruption.
4. **MAJOR (fixed):** absolute local model paths changed `.translate` identity and
   config checksums. Absolute paths now normalize to the model-directory basename.

The `.ppkg` 100k path also had a clear hot-path defect: `relationship=None` matched
every entry with a NULL relationship. New packages now contain separate subject,
scope, and relationship routing indexes, and routing uses bounded indexed coarse
queries before CPU scoring. SQLite journal, synchronous, transaction, checkpoint, and
semantic-checksum behavior is unchanged.

All 49 active tests passed in 45.05 seconds, including both exact Pythia-1.4B CUDA
regressions. The added concurrent SQLite regression also passed independently after
the full run. `git diff --check` is part of the final verification recorded below.

## Correctness and adversarial audit

The active tests cover empty/one/full/overflow state; protected permanent capacity;
importance-aware rejection and eviction; duplicate entity/relation identities;
contradictory values; long create/modify/merge/invalidate chains; correction authority;
stale, historical, and invalidated state; malformed scores/enums; long Unicode labels;
tokenizer-independent unseen names; checksum/protocol/model incompatibility; repeated
save/load; top-k; cold `.ppkg` reload; and concurrent/interleaved SQLite reads/writes.

Operation results:

| Operation | Result |
|---|---|
| `CREATE` | Fixed preallocation, identity-safe canonical admission |
| `MODIFY` | In-place latest-state replacement; explicit correction resists inference overwrite |
| `KEEP` | Refreshes timestamp without reallocating |
| `MERGE` | Generic cache semantic merge retained; canonical merge restricted to the same entity and relation |
| `INVALIDATE` | Valid bit cleared, value zeroed, canonical IDs cleared; router cannot select it |
| `IGNORE` | No state or allocation mutation |

No invalidated or stale state reappeared in routing or CUDA generation. The mutation
and invalidation tests preserve one current canonical version and remove its causal
effect after invalidation.

## Performance profile

All times are medians from `artifacts/active-system-audit.json`. CPU cache/router
measurements use float32 to expose fixed allocation directly; production P-cache uses
configured dtype. Generation figures use the selected Pythia-1.4B CUDA adapter.

### P-cache and canonical router

| Slots | Query construction | Index hydration | Router rank | P allocation | Router index |
|---:|---:|---:|---:|---:|---:|
| 64 | 0.260 ms | 14.91 ms | 0.178 ms | 134,464 B | 33,856 B |
| 128 | 0.261 ms | 30.12 ms | 0.172 ms | 268,928 B | 67,712 B |
| 256 | 0.257 ms | 59.16 ms | 0.177 ms | 537,856 B | 135,424 B |
| 512 | 0.264 ms | 117.42 ms | 0.182 ms | 1,075,712 B | 270,848 B |
| 1,024 | 0.264 ms | 233.00 ms | 0.198 ms | 2,151,424 B | 541,696 B |

Ranking is cheap; rebuilding tokenizer-independent byte anchors from every label is the
dominant cost and scales linearly. The Pythia wrapper currently rebuilds this index for
each generation call. Caching an index behind an explicit store-mutation generation is
the highest-priority remaining performance optimization.

### Translator and generation

The selected translator has 2,707,464 parameters (10,829,856 bytes in float32).
Translation plus gating measured 0.607 ms CPU and 1.204 ms CUDA for a 16-token batch.
The synthetic CUDA profile copied 164,096 input bytes, used 8.91 MB additional active
allocation and peaked at 9.44 MB beyond already-loaded translator weights.

Matched end-to-end Pythia latency was 17.449 ms frozen and 19.283 ms with relevant
P-package state. Rejected-but-present states still pay routing/index overhead:
wrong-entity 19.297 ms, wrong-relation 18.961 ms, historical 19.348 ms, while an empty
invalidated store was 17.605 ms. Extra prompt tokens and recent-KV source tokens are
both zero.

At 100k, measured Python peak allocation for the selected lookup was 87,891 bytes and
inactive VRAM was zero. `EXPLAIN QUERY PLAN` confirms covering searches through
`entry_subject_route` and `entry_scope_route`, followed by bounded CPU scoring; the
router no longer scores all 100k entries.

Compared with the immediately preceding 100k profile, header routing fell from
255.078 ms to 67.10 ms (3.80x). Row hydration fell from 0.203 to 0.118 ms and canonical
conversion from 0.713 to 0.495 ms. Cold checksum time remained a boundary-only cost
(843.619 ms before, 823.89 ms now). A normal top-k query performs zero whole-package
checksum calls.

The three added covering indexes increase a 100k synthetic package from approximately
37 MB in the earlier profile to 58.7 MB. This is an intentional disk-space/lookup-time
tradeoff; it does not change loaded rows, RAM scaling, VRAM scaling, or canonical data.

## Router scaling attribution

Immutable pre-fix results remain 128=100%, 256=95%, 512=85%. The matched post-fix
run produced 100% top-1, 100% top-4 recall, and MRR 1.0 at 4, 20, 64, 128, 256, 512,
and 1,024 slots. No entity, relation, historical, hard-negative, or byte-anchor
collision failures occurred.

The decisive evidence is that the old oracle-query result degraded identically to the
learned query. Controlled reproduction found repeated factorized vectors being merged
across canonical identities before ranking. Restricting merge candidates to the same
entity/relation fixes the storage alias. Increasing top-k was not used as a remedy.

Linear scoring latency remains sub-millisecond at these capacities, but label/index
hydration is linear and is separately classified as a performance issue.

## `.translate` portability audit

Model-independent modules contain no tokenizer IDs, GPT-NeoX layer names, base weights,
conversation state, or model hidden vectors. Model width, attachment layers, model ID,
revision, config checksum, query/value/gate weights, canonical protocol and checksums
are isolated in `.translate` metadata and tensors.

GPT-NeoX assumptions are confined to `pythia_split_translate.py`, where they are
**INTENTIONAL** model-adapter behavior: `base_model.gpt_neox.layers`, Pythia hidden
width, and hook return shape. Evaluation code is likewise Pythia-specific but is not
canonical runtime state. Absolute-path normalization fixed an accidental local-path
coupling.

A second-architecture structural proof uses a tiny GPT-2 decoder with
`transformer.h`, the same `CanonicalPStore`, the same `CanonicalPRouter`, and a new
32-wide `.translate` package. Injection changes logits, invalidation restores exact
base behavior, base gradients remain zero, save/load passes, and no canonical protocol
change is required. This proves the interface boundary structurally. Semantic quality
with a second pretrained decoder and trained compatibility package remains unverified
and is a **MAJOR** portability limitation, not retroactively claimed as proven.

## `.ppkg` maturity

- One weak event does not promote; three independent events do.
- Cross-context/connectivity score 2.5865 exceeds five narrow-context repetitions at
  1.8000.
- Unsupported model claims do not promote; explicit user correction promotes and
  supersedes the old conclusion without deleting evidence/history.
- Technical, creative, and relationship-specific routes are all correct; irrelevant
  query loads zero entries.
- Undo history, archive evidence references, deterministic semantic checksum, cold
  reload, top-1/top-4/top-8, selected-row-only activation, and P-cache-to-evidence gating
  pass.
- Full checksum validation occurs at open/load, explicit verify, export/snapshot,
  checkpoint, and dirty close. Normal routing, polling, evidence push, and row hydration
  do not hash the package.
- SQLite remains `synchronous=FULL` with transactional writes and clean/dirty checkpoint
  metadata. Concurrent reader/writer testing passed.

Remaining maturity issue: arbitrary personality strings are converted through a
24-entity/3-relation/36-value learned factorized representation whose weights are
reconstructed by a fixed training recipe rather than shipped as a checksummed canonical
protocol artifact. The `.ppkg` itself is correctly symbolic and model-independent, but
fresh-runtime canonical conversion and broad vocabulary portability rely on this
external recipe. This is **MAJOR** and should be resolved without putting model-native
state into `.ppkg`.

## Integrity boundaries

| Format | Integrity action | Hot-path hashing |
|---|---|---|
| Canonical P snapshot | Tensor+metadata checksum on save/load; format and corruption rejection | None after load |
| `.router` | Weight checksum and protocol/config validation on load | None during route |
| `.translate` | Weight checksum plus model ID/width/config/layer/protocol validation on load | None during injection |
| `.ppkg` | Semantic checksum at open, explicit verify, export, checkpoint, dirty close | None during lookup/evidence push |

Semantic state round-trips deterministically. Safetensors header key ordering is not
used as identity; the deterministic content checksum is. Canonical files contain no
base weights, model tokens, optimizer state, conversation contents, or model-native
hidden representations.

```text

                         ^                 ^                    |
                         |                 |                    v
               Personality activation     +---------- Pythia adapter -> frozen LM
                         ^
                 PersonalityPackage <- indexed SQLite storage
```

| Coupling | Classification | Finding |
|---|---|---|
| P-cache -> Pythia | CLEAN | No dependency |
| Canonical router -> model hidden width/tokenizer | CLEAN | No dependency; byte encoder is tokenizer-independent |
| Pythia adapter -> GPT-NeoX layers | INTENTIONAL | Model-specific behavior is isolated in adapter |
| `.ppkg` router -> SQLite internals | CLEAN after fix | SQL is encapsulated by package `routing_headers`; router scores canonical headers |
| `.ppkg` -> translator implementation | SHOULD REMOVE | It imports shared `ByteEntityEncoder` from the split-translator module; class is canonical but located in a model-compatibility module |
| `.translate` -> `.ppkg` file layout | CLEAN | No dependency |

| Canonical protocol -> model config checksum helper | SHOULD REMOVE | Generic helper is harmless but belongs at the translate boundary |
| Evaluation modules -> Pythia/tokenizer | ACCEPTABLE | Evaluation-only, not canonical runtime/package state |
| Active runtime -> `Archive/` | CLEAN | No imports or paths |

`artifacts/active-system-audit.json`.

## Memory hierarchy invariant

The audited implementation preserves the intended ownership:

```text
Recent KV  -> exact recent wording
P-cache    -> current mutable state
P-package  -> durable, slow-changing personality conclusions
Tool-KV    -> reserved; no implementation started
Archive    -> exact historical record and superseded repository eras
.router    -> canonical state selection
.translate -> frozen-model compatibility and injection
```

P-package evidence references archive events rather than storing transcripts. P-cache
does not absorb durable personality policy. `.ppkg` activation creates a temporary
bounded canonical store and discards model-space translation after generation.

## Component scorecard

### P-cache

- Correctness: **CLEAN after fixed BLOCKER** — identity-safe merge, metadata validation,
  stale/invalidation exclusion, all operations and capacity pressure pass.
- Performance: **MINOR** — mutation is fixed-allocation; no hidden reallocation.
- Scaling: **CLEAN** through 1,024 storage slots in the audit.
- Memory: **CLEAN** — fixed by configured capacity.
- Portability: **CLEAN** — canonical data is model-independent.
- Coupling: **CLEAN**.
- Known issues: router-index invalidation/versioning is absent.
- Recommended work: add a mutation generation counter consumed by cached router indexes.
- Status: **CLEAN**.

### Canonical `.router`

- Correctness: **CLEAN after fixed BLOCKER** — 100% top-1/top-4 and MRR 1.0 through
  1,024 on the matched workload; wrong entity/relation/history/stale/invalidation pass.
- Performance: **MAJOR** — score/rank is sub-ms, but per-call index hydration is
  14–229 ms over 64–1,024 slots.
- Scaling: **MINOR** — linear scan is currently acceptable at proof capacities.
- Memory: **CLEAN** — bounded by slot capacity.
- Portability: **CLEAN** at canonical selection boundary.
- Coupling: **SHOULD REMOVE** shared byte encoder location.
- Known issues: no cached index keyed to a store mutation version.
- Recommended work: cache canonical entity anchors/index and invalidate explicitly on
  create/modify/merge/invalidate.
- Status: **MAJOR** performance issue, no correctness blocker.

### Model-specific `.translate`

- Correctness: **CLEAN** on Pythia — causal A/B, wrong-state rejection, invalidation,
  gradient isolation, checksum and compatibility tests pass.
- Performance: **CLEAN** — ~0.49 ms translation/gate kernel; generation overhead ~1.8 ms
  excluding disk retrieval.
- Scaling: **CLEAN** with bounded top-k state.
- Memory: **CLEAN** — 2.707M trainable compatibility parameters; no base/P contents.
- Portability: **MAJOR** — GPT-2 structural proof passes, but trained semantic quality on
  a second pretrained architecture is unverified.
- Coupling: **INTENTIONAL** Pythia layer access is isolated; absolute-path coupling fixed.
- Known issues: attachment implementation is not yet factored behind a formal generic
  decoder-hook protocol.
- Recommended work: train/evaluate one small non-GPT-NeoX compatibility package without
  changing canonical state.
- Status: **MAJOR** portability evidence gap, Pythia path ready.

### P-package `.ppkg`

- Correctness: **CLEAN** for mechanical policy — promotion, authority, contradiction,
  rollback, context, evidence links, cold reload, and concurrency pass.
- Performance: **MINOR after optimization** — 100k header routing 66.54 ms, bounded 152
  headers and four hydrated rows; further CPU scoring optimization is available.
- Scaling: **CLEAN** to 100k for bounded active memory; 1M was not run because 100k
  already characterized the indexed/candidate-bound behavior.
- Memory: **CLEAN** — 87.9 KB measured Python peak, zero inactive VRAM, 1,077 active
  canonical bytes for top-1.
- Portability: **MAJOR** — package bytes are portable, but canonical representation
  weights/large open vocabulary are not yet a shipped protocol artifact.
- Coupling: **SHOULD REMOVE** byte encoder import location; no translator/file-layout
  dependency.
- Known issues: Python byte-feature scoring dominates bounded candidate routing;
  canonicalizer hashes arbitrary fields into small fixed embedding vocabularies.
- Recommended work: persist/version the model-independent canonical representation and
  move shared byte features into the canonical protocol module before broader `.ppkg`
  claims.
- Status: **MAJOR** portability/maturity issue; disk/integrity/mechanical layer passes.

## Ranked remaining work

1. **MAJOR:** persist and checksum the canonical factorized representation (or define a
   deterministic non-trained canonical encoder) so `.ppkg` activation never relies on
   retraining an external recipe and arbitrary values do not silently collide in a
   24/3/36 vocabulary.
2. **MAJOR:** cache canonical router indexes behind explicit P-store mutation versions;
   index hydration, not ranking, dominates active latency.
3. **MAJOR:** complete a trained semantic portability proof on one non-GPT-NeoX
   pretrained decoder using only a new model-specific `.translate` package.
4. **MINOR/OPTIMIZATION:** vectorize or cache byte-entity scoring for the bounded `.ppkg`
  candidate set; current 100k header route is 67.10 ms.
5. **MINOR:** relocate the shared byte encoder and model-config checksum helper to make
   conceptual module ownership match the dependency diagram.

No severity was assigned merely to produce findings. Current P-cache correctness and
integrity are clean; remaining high-priority items are measured portability and latency
boundaries rather than hidden state corruption.
